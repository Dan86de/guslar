# Perform a rite

Besides taking a contract, a user sends hunters on the other rites of the pipeline straight from the world, so no step of it needs a terminal.
A region's plaque opens its own rites: hear the villagers (`/interview`), draft the bounty (`/write-spec`) and set the proof of kill (`/make-verify`).
A village with no contracts yet offers to post them (`/write-slices` on its spec), and a pending contract offers to inspect its trophy (`/implement-slice --signoff`).
Each rite sends a hunter with that skill into the region's repo, bound to its region or village, with a permission mode chosen as for a take.
A region takes one hunter at a time for its own rites, as a village does for its own.

## Entry points

- The plaque of a claimed region on the map, which opens its rites, then a rite and a permission mode.
- The `Post contracts` button of an opened notice board with no contracts posted, then a permission mode.
- The `Inspect` button on a pending contract of an opened notice board, then a permission mode.
- The world broadcast on `/ws` (and `/api/world`), which carries every hunter with its rite, and the village and contract it is bound to.

## Steps

- Run `verify write repos/bogwater/.scratch/slices/drain-the-bog.json '{"spec":".scratch/specs/drain-the-bog.md","branch":"main","slices":[{"id":"S1","title":"Dig the first ditch","autonomy":"afk","blocked_by":[]},{"id":"S2","title":"Raise the dyke","autonomy":"hitl","blocked_by":["S1"]},{"id":"S3","title":"Lay the plank road","autonomy":"afk","blocked_by":["S1"]}]}'`.
- Run, in this order: `verify git repos/bogwater init --initial-branch=main`, `verify git repos/bogwater add .scratch/specs`, `verify git repos/bogwater commit -m "Add the specs"`, `verify git repos/bogwater switch --create slices/drain-the-bog`, `verify git repos/bogwater commit --allow-empty -m "Dig the first ditch" -m "Slice: S1"`, `verify git repos/bogwater commit --allow-empty -m "Raise the dyke" -m "Slice-Pending: S2"`. ## Behind it

- **The claude Guslar started for each rite.** `verify read claude.log` shows five claudes, each `started in <run folder>/repos/bogwater` with `GUSLAR_HUNTER_ID=` set to its hunter's id, and each first `stdin:` a user message whose text is, in the order they were sent: `/interview` with `--permission-mode default`; `/write-slices .scratch/specs/ward-the-well.md` with `--permission-mode acceptEdits`; `/implement-slice .scratch/slices/drain-the-bog.json --signoff S2` with `--permission-mode default`; `/write-spec` with `--permission-mode acceptEdits`; `/make-verify` with `--permission-mode bypassPermissions`. There is no sixth: the refused rite and the refused take started nothing.
- **`/api/world` agrees with the broadcast.** `verify http /api/world` prints `HTTP 200 application/json` and the same three hunters.

## Gotchas

- The run's Guslar starts `claude` as the verify skill's recorder, which writes `claude.log` and does nothing a skill would: no spec, slices file or verify skill lands, so the villages and stages stay as the preconditions laid them.
- Gates are files: once `gates/end` is open, every claude that replays after it passes it at once, so the later rites come back within a second or two. Wait with `wait-for` on the state, never on `is out to`.
- Hunters are named in a fixed order, the first name no hunter on the map is using, so a rite that sends a returned hunter home can reuse its name.
- A rite with no contract comes back with a trophy when its turn ends well and wounded when it fails; a reply in its journal sends it out again. An inspection is paid only once its contract is done.
- A pending card shows either its `Inspect` button or the line of the hunter on it, never both: while a hunter is out on it, the line; once the hunter is back, `Inspect`.
- `verify click "Bogwater Reach"` matches the region's plaque and its villages; name the plaque `Rites of Bogwater Reach`.
